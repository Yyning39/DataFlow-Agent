# v9 本地混合 Schema 检索评测报告

## 实验契约

- 数据：BIRD Mini-Dev SQLite，统一 22 条公开问题（同一 manifest SHA-256）。
- 模型：`deepseek-v4-flash`，温度 `0.0`，provider `proxy/deepseek`。
- v9：本地 SchemaHybridRetriever 开启，索引版本 `v9`，每题 60 秒上限。
- 对照：历史 v4 严格评测，同一问题集，120 秒上限。两次均无超时；超时预算不同仍需在后续正式报告中统一。

## v9 检索可观测性

- `schema_local_hybrid_used_rate=100%`：每题均进入本地混合召回。
- `schema_local_hybrid_cache_hit_rate=47.62%`：同一数据库重复访问时命中已持久化索引。
- 平均候选数 6.76，平均最高混合分 0.3088，平均本地检索耗时 0.0126s。
- `schema_retrieval_empty_rate=100%` 仍反映底层 Chroma 没有返回候选；v9 的价值是把该失败显式转为可复现的本地索引召回，而不是把空结果当作正常向量召回。

## 结论与下一步

在相同公开问题集上，v9 已显著提升 SQL 可生成率和执行成功率，严格结果正确率有小幅提升；瓶颈从“Schema 召回不可观测”转移到模型 SQL 语义/聚合正确性。下一轮应：

1. 以同一 60 秒预算重新跑 v8 控制组，再做严格 A/B；
2. 对 13 个错误样本按 Schema 召回、指标语义、SQL 结构、结果形状分类；
3. 再评估可用的真实 Embedding 后端，保持 v9 文档协议和本地 fallback 不变。
